## Finding 1 in detail, and the options

The cause is that each reader reports the first defect it meets while scanning, and the two scan in a different order. The code is only fixed for one defect at a time, so
no conformance case catches it and neither implementation is wrong against the text. Options:

- **A. Say so (smallest).** Add a sentence to `docs/interop/UAI-1.md` that the code is fixed only when a text has one defect. No code change; honest, but leaves receivers to cope.
- **B. Fix the order.** Add a sentence fixing a reader order (for example syntax before duplicate keys before number form before range), change one or both readers, and add
  suite cases. This changes the specification and the suite (72 to more cases), so every count in the docs and CI moves, and any outside implementation would need to follow.
- **Recommendation:** A now, B only if an outside implementer reports it. Neither is done here.

## What this audit did not do

- It is not independent, and it is not a penetration test. Nobody outside the project has implemented UAI-1, and the fuzz compares two implementations from one team.
- It did not review the Node source line by line, measure signature timing, test across hosts, or test TLS, a real HSM or a real network partition.
- It did not run any live provider call, so nothing here says how any model answers.
- It did not read the 37 other repositories that pin CNS.
